    Asgard¶

    Upgrading from an earlier version?

    Version 0.6.0 has breaking changes to scheduled tasks, watchers and sh. Read Breaking Changes before you upgrade.


    "Loki collects the tricks.
    Thor of Asgard runs them."         		Key Features
    • Tasks in plain Ruby: a task is a method in a .loki file; every Thor DSL word (desc, method_option, long_desc, map, subcommand) works as written
    • Dependencies: depends_on runs prerequisites first, in sequence or in parallel stages, each at most once per run
    • Shell commands: execute shell scripts through user-defined shell environments, as foreground or background processes
    • Variables and helpers: @@name values shared by every task, helper methods usable in help text and task bodies alike
    • Subcommands: group tasks as asgard db migrate or asgard server start
    • Environment: dotenv loads a .env file; env(:port, "3000") reads a variable with a default
    • Auto-discovery: run asgard from any subdirectory; it finds the project's .loki by walking up
    • Multi-file projects: split tasks across *.loki files and pull them in with import
    • Scheduled tasks: schedule :backup, at: "02:00" and asgard schedule install hand a task to launchd or systemd
    • Watched files: watch :test, paths: "lib" and asgard watcher start run a task whenever files change
    • Background jobs: sh "mkdocs serve", background: true starts a job that outlives asgard; asgard jobs lists, stops and restarts it
    • Built-in flags: --version, --debug, --verbose and --doctor, which diagnoses a project's task files

    Asgard is a command-line task runner for any project. You describe the tasks a project needs (build it, test it, deploy it, serve its docs) as short Ruby methods in a file named .loki, and asgard <task> runs them. Asgard orders prerequisites for you, runs independent ones in parallel, and can keep running tasks when you are not at the keyboard: on a timer, when files change, or as a background process you manage later.

    The name is a small joke: Thor is the command-line toolkit asgard is built on, Asgard is where the tasks live, and Loki, the .loki file, holds all the tricks.

    Quick Start¶

    # Install the command
gem install asgard

# Mark your project root
cd ~/work/myproject
touch .loki

# Add a first task
cat >> .loki << 'EOF'
class Tasks
  desc "Say hello"
  def hello = puts "Hello from Asgard!"
end
EOF

# Run it
asgard hello

    Hello from Asgard!

    asgard help lists every task the project defines, and asgard help hello shows the help for one of them.

    How It Works¶

    When you type asgard build, asgard looks for a file named .loki in the current directory, then in its parent, and so on up to the root of the filesystem. The first one it finds marks the project root, so the command works from any subdirectory of the project.

    That .loki file is plain Ruby. Asgard has already defined a class named Tasks; your file reopens it and adds methods. Each public method with a desc is a task you can run from the command line:

    class Tasks
  desc "Compile the project"
  def build = sh "rake build"

  depends_on :build
  desc "Run the tests"
  def test = sh "rake test"
end

    Only .loki loads on its own. When a project outgrows one file, .loki says what else to load with import "*.loki", and every imported file reopens the same Tasks class.

    Asgard is built on Thor, so the words you may know from other Ruby command-line tools work unchanged inside a .loki: desc, method_option, class_option, long_desc, argument, default_task, map and subcommand. Asgard adds its own on top: depends_on, sh and shebang (with background: for jobs), shell, default_shell, helper, header, footer, dotenv, schedule and watch.

    Requirements¶

    • Ruby 4.0 or later.
    • macOS or Linux for scheduled tasks and the file watcher (launchd on macOS, systemd user timers on Linux).
    • A POSIX system for background jobs (sh ..., background: true and asgard jobs), which need fork, setsid and /bin/sh. Everything else works wherever Ruby does.
    • A C++17 compiler at install time: gem install asgard compiles one native extension. Xcode's command-line tools or a distribution's build-essential package is enough.

    Asgard is on RubyGems; the source and issue tracker are on GitHub.
